# uzum_cat — мониторинг категории Uzum Market

Пакет для снятия ежедневных снапшотов категории на uzum.uz (цены, рейтинги,
число отзывов, магазины) через неофициальное клиентское GraphQL/REST API —
то же самое, которое использует фронтенд сайта.

**Важно:** это реверс-инжиниренный доступ, не официальный Seller API.
Схема запросов/ответов может измениться в любой момент без предупреждения.
Годится для собственного мониторинга ниши, не для критичного
бизнес-процесса. Не увеличивай частоту запросов и не убирай паузы между
страницами (`delay_seconds`) — вежливый темп снижает риск блокировки.

## Установка

```bash
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -e ".[dev]"
playwright install chromium
```

## Как это устроено

- **`uzum-cat discover <url категории>`** — открывает браузер (не headless,
  чтобы проще проходить анти-бот проверки), заходит на страницу категории,
  скроллит и слушает сетевые запросы к `graphql.uzum.uz`/`api.uzum.uz`.
  Для каждого ответа пытается автоматически распознать список товаров
  (`uzum_cat.parser.find_product_list` — эвристика по характерным ключам
  карточки товара, а не жёстко зашитый путь в JSON, так как схема ответа
  может немного отличаться или измениться). Если распознавание сработало —
  сразу сохраняет найденный запрос как `request_template.json`. Если нет —
  сохраняет все пойманные запросы в `captured_requests.json`, и нужный
  объект придётся выбрать руками (см. ниже).

- **`uzum-cat harvest`** — по шаблону `request_template.json` проходит
  категорию постранично, извлекает товары той же эвристикой и сохраняет
  снапшот в SQLite (`uzum_cat.db`) + опционально в CSV (`--csv`).

- **`uzum-cat export`** — выгружает накопленную в БД историю снапшотов
  (или один конкретный снапшот, `--snapshot-id`) в CSV.

**Проверено вживую** (2026-09-13) на категории `zhenskaya-odezhda--99`:
запрос `MakeSearch_ItemsAndFilters` на `graphql.uzum.uz` отдаёт список
товаров без данных о продавце (поле `shop` в CSV будет пустым) — id,
название, цена, рейтинг и число отзывов извлекаются корректно. Полный
JSON каждого товара всё равно сохраняется в колонке `raw_json` в SQLite,
так что данные не теряются, если что-то понадобится достать вручную.

## Быстрый старт

```bash
uzum-cat discover "https://uzum.uz/ru/category/zhenshchinam-1"
```

Если `request_template.json` не создался автоматически:

1. Открой `captured_requests.json`.
2. Найди объект, который реально вернул список товаров (обычно в
   `post_data` есть слова `query`/`variables`/`search`/`category`/`offset`).
3. Скопируй этот **один** объект (`url`, `headers`, `post_data`) в
   `request_template.json` рядом с проектом.

Затем, если нужно, скопируй `config.yaml.example` в `config.yaml` и поправь
`pagination_field`/`page_size` под то, что видно в `variables` пойманного
запроса.

```bash
uzum-cat harvest --csv snapshot.csv
```

## Автоматизация

`.github/workflows/daily.yml` — прогоняет `harvest` раз в сутки в GitHub
Actions и коммитит снапшот (CSV + SQLite) обратно в репозиторий.

Для этого нужно один раз положить содержимое `request_template.json` в
секрет репозитория `REQUEST_TEMPLATE_JSON` (Settings → Secrets and
variables → Actions). **Учти:** токен авторизации внутри — обычный JWT,
он протухает раз в 1-2 недели. Когда воркфлоу начнёт падать с 401 —
прогони `uzum-cat discover` заново и обнови секрет.
